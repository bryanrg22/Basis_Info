# Stage 3 specification: pipeline parity in `basis/`, legacy packages removed

Companion to BUILD_PLAN §4 (C8-C14), §5, §6.1, §6.2, §6.6, §6.7, §13.2 and S2_SPEC §4. Stage 3 replaces the Stage 2 stub activity bodies with the real pipeline, migrated module by module from `agentic/`, `evidence_layer/`, and `vision_layer/` into `basis/`, with tests, and then deletes the legacy packages and their tests. The workflow (S2) does not change.

## 0. Rules

- Deterministic first: rule tables, formulas, cost tables, regex, cleaners, parsing, chunking, BM25, fusion, validators are pure functions with unit tests. LLM calls are isolated behind one interface and are the only non-deterministic code.
- One model-call interface: `basis/llm/` provides `ChatProvider` (Protocol) with `AzureOpenAIProvider`, `OpenAIProvider`, and `ScriptedProvider` (tests). Every call records an `llm_calls` row (provider, model, prompt_version, tokens, cost, latency) and checks the remaining study budget before calling; exceeding it raises `BudgetExceededError`.
- Structured outputs only: every LLM call declares a pydantic response model and uses the provider's JSON-schema/structured-output mode; the raw response is stored in the relevant `raw` JSONB column.
- Tools the residual classifier may call are built per study with `study_id` and corpus version bound at construction; the model never supplies them. Tool allowlist per call. Tool results are passed as JSON text with a `name` on the tool message (fixes W5).
- Citations: every citation must resolve (`chunks.id` exists in the corpus version used) and the excerpt must be a normalized substring of the chunk text; a citation failing either is dropped and the asset is marked `needs_review` with reason `citation_unverified`. A classification with zero verified citations and `method="llm"` is `needs_review`.
- Client files never enter the repo. Unit and node tests use synthetic fixtures under `tests/fixtures/synthetic/` generated by scripts in `tooling/fixtures/` (a fake URAR-style PDF with known field values and two tables; six synthetic room photos rendered with PIL and labelled text; a 40-chunk mini reference corpus). Real-document evaluation lives in `backEnd/evals/` and reads `BASIS_EVAL_DATA_DIR`; only the orchestrator runs it.
- Prompts are versioned files under `basis/prompts/<name>/<version>.md` with a registry; `prompt_version` is recorded on every call.

## 3. Retrieval details (S3-A)

- BM25: `rank_bm25.BM25Okapi` over `irs_tokenize` built from `chunks` rows of a corpus version at worker start and cached per `corpus_version_id` (`functools.lru_cache`-style registry with explicit `warm(version_ids)`); rebuild time logged; a study corpus is built on demand after `ingest_appraisal`.
- Embeddings: `sentence-transformers/all-MiniLM-L6-v2`, normalized, 384-d; model loaded once per process; `embedding_model` recorded on `corpus_versions`. Vector search via SQL `ORDER BY embedding <=> :q LIMIT k` with an HNSW index (migration `0004_chunks_hnsw`, `vector_cosine_ops`).
- Ingestion CLI `python -m basis.retrieval.ingest --corpus reference --pdf <path> --doc-id IRS_PUB_946_2024 --version-note "..."` creating a new `corpus_versions` row (immutable); tables stored whole in `evidence_tables` with surrogate chunks; chunk_key = `{doc_id}:{page}:{ordinal}` so re-chunking is diffable.
- Fusion: both weighted max-normalized sum (current behaviour) and RRF (k=60); default from settings `retrieval_fusion="rrf"` after the eval compares them (orchestrator decides from §6 numbers; builder implements both and tests both).
- Verify: `verify_citation(chunk, excerpt)` normalizes whitespace/case/quotes/dashes and checks containment; `resolve_citation(store, chunk_id, version)`.
- Tests: migrate `test_tokenizers` → `tests/unit/retrieval/test_tokenizer.py`; add `test_chunker.py`, `test_tables.py` (synthetic PDF), `test_bm25.py`, `test_fusion.py` (weighted vs RRF, ties, weight extremes), `test_verify.py`, `tests/integration/retrieval/test_store.py` (ingest the mini corpus; vector neighbor; study isolation with two studies; version immutability; old citations resolve after a v2), `test_cold_warm.py` (second query does not rebuild), `test_ingest_cli.py`.

## 4. Extraction and vision details (S3-B)

- Azure DI client wraps `azure.ai.documentintelligence` `prebuilt-layout` with key-value pairs; results mapped through `field_mappings` (fix the `CRITICAL_FIELDS` mismatch, which removes the A.8 xfail), then cleaners, then `validate_fields` (types, ranges, cross-field: `total_rooms >= bedrooms + bathrooms`, `final_market_value` within 50% of cost approach when both present), then a single-shot structured LLM call only for critical fields that are missing or failed validation, with the page text of the relevant section as context, recorded with `source="llm"` and confidence from the provider's self-report capped at 0.6.
- Confidence gate: `needs_review` when any critical field confidence < `settings.extraction_review_threshold` (default 0.90, tuned later by the eval) or any validation failure.
- Vision: `analyze_photo` prepares the image, calls the provider with the versioned prompt and `PhotoAnalysis` schema (room_type enum incl. `ambiguous`/`exterior`/`mechanical`, floor hint, components with label from a controlled vocabulary of ~60 labels plus `other`, material, attachment, confidence), stores raw, maps to `rooms`/`photo_rooms`/`components` rows; provider pool with concurrency from settings and fallback to the second provider on 429/5xx only; cost charged to the budget.
- Tests: migrate `test_azure_di_cleaner` → `tests/unit/extraction/test_cleaners.py`; add `test_field_mappings.py` (every critical field is produced; A.8 fixed), `test_validation.py`, `test_section_mapper.py`, `test_pipeline.py` (recorded/synthetic Azure DI payload fixtures built by hand from the SDK types; low confidence → review; LLM fallback only for failed criticals using `ScriptedProvider`), `tests/unit/vision/test_schemas.py`, `test_analyze.py` (scripted provider; invalid JSON → retry once then `needs_review`; budget exceeded → non-retryable), `test_image_prep.py`, `tests/unit/llm/test_providers.py` (request building, usage parsing, cost table, budget charge, scripted provider), `test_prompts.py` (registry, versions immutable).

## 5. Classification, domain, evidence, export (S3-C)

- `basis/domain/rules.py`: the rules table with citations as `(doc_id, page, excerpt)` resolved to chunk ids at ingestion time by a one-off script and stored in `rules_citations.json` keyed by rules_version; `lookup(label, material, attachment, property_class) -> RuleHit | None` with alias normalization.
- Router: rule → `classification_cache` (key = normalized label|material|attachment|property_class|rules_version) → residual LLM with tools `search_reference`, `get_chunk`, `get_table` (max 3 tool calls, 4 iterations, 1 retry on invalid JSON, timeout 60 s), structured `Classification` output with `citations: list[CitationClaim]`; verification per §0; result rows in `assets` + `citations`; `method` recorded; cache written only from engineer-approved assets (S4 hook; S3 provides `promote_to_cache(asset_id)`).
- Takeoffs and costs: formulas and tables as pure functions with inputs recorded in `takeoffs.inputs`; cost year and location factor from settings; cross-validation warnings set `needs_review`.
- Evidence pack: assemble per revision from `assets`+`citations`+chunk text; export JSON (assets with buckets, quantities, costs, citations with excerpts and page refs) and CSV, written to storage, sha256 recorded; deterministic ordering.
- Behavioral evals (`tests/evals/behavior/`, scripted provider, PR gate) exactly per BUILD_PLAN §6.6: injected instructions in document text and in photo-derived text change nothing; model asks for another study's corpus → tool refuses and trace shows it; model output cannot change status; missing evidence → `needs_review`; fabricated citation rejected; caps enforced.
- Eval harness `backEnd/evals/`: loaders (`appraisal_fields`, `photo_rooms`, `photo_components`, `assets`, `retrieval_qrels`), metrics (`field_accuracy` exact/normalized with per-field tolerance, `classification_metrics` per class F1 + Wilson interval, `ir_metrics` via `pytrec_eval` nDCG@10/recall@5,10/MRR, `citation_support_rate`, clustered standard error by document), `run.py` producing `eval_runs`/`eval_results` rows and a Markdown report; unit tests on the metrics with toy data.
- Tests: migrate `test_static_rules` → `tests/unit/domain/test_rules_table.py`; add `test_takeoff_formulas.py`, `test_cost_tables.py`, `test_validators.py`, `test_cross_validation.py`, `tests/unit/classify/test_router.py`, `test_tool_loop.py` (caps, invalid JSON, unknown tool, malformed args, infinite loop, provider error), `test_tools_scope.py`, `test_citation_verify.py`, `tests/unit/evidence/test_pack.py`, `test_export.py` (byte-identical for same revision), `tests/node/test_process_assets.py`, `test_export_report.py`, `tests/unit/evals/test_metrics.py`.
