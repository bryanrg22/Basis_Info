# Test ledger

Every test file, the invariant it protects, and the release that introduced it
(BUILD_PLAN section 0, rule 5). Changing a behavior means changing its test in the same
change, with the reason stated in the commit message and in the Notes column here.

Run everything from `backEnd/` with `uv run pytest -q`. `-m "not legacy"` runs only the
basis suite; `-m "not slow"` skips the subprocess-based checks; `-m integration` runs the
tests that need Docker (a `pgvector/pgvector:pg16` container via testcontainers). The
Temporal-backed ones (S2) also start a Temporal dev server with
`WorkflowEnvironment.start_local()`: the `temporal` CLI when it is on `PATH`, otherwise
the SDK downloads it.

Retrieval (S3-A) caches, for CI: the chunker's tiktoken `cl100k_base` file is downloaded
on first use (to `TIKTOKEN_CACHE_DIR`, default `$TMPDIR/data-gym-cache`), so CI needs
network on the first run or should cache that directory with a fixed
`TIKTOKEN_CACHE_DIR`; `tests/integration/retrieval/test_real_embedder.py` runs only when
`~/.cache/huggingface` already holds `sentence-transformers/all-MiniLM-L6-v2` (cache it
in CI, or the three tests skip). Every other test uses the hash embedder.

## regression (reproduced legacy defects, strict `xfail` until fixed)

Each test asserts the correct behavior and is marked `xfail(strict=True)`, so it fails the
run the moment the behavior is fixed; the fix removes the mark in the same change.
Run with `-m regression`. Sources: REVIEW_AND_PLAN.md A.3 (W1, W2, W3, W5) and A.8.

replaced by passing lifecycle tests: W1 `test_legacy_graph_reachability.py` (every node
reachable from START) -> `tests/lifecycle/test_happy_path.py` (every stage runs, in
order, to `completed`); W2 `test_legacy_resume_runs_expected_node.py` (resuming runs the
next step, never extraction again) -> `tests/lifecycle/test_restart_recovery.py`; W3
`test_legacy_rejection_not_recorded_as_approval.py` -> `tests/lifecycle/test_reject_paths.py`
(with `test_stale_approval.py` and `test_concurrent_decisions.py`). W5 stays for S3-C.

is produced by the mapping tables). `basis/extraction/field_mappings.py` derives
`CRITICAL_FIELDS` from the field catalogue and keys every field as `section.field`; the
invariant now passes in `tests/unit/extraction/test_field_mappings.py`
